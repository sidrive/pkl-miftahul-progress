# Laporan Analisis Refactor State Management ke Pinia (M4.W1.T4)

## 1. Alur Logis `State` -> `Getters` -> `Actions` di `todoStore.js`

Dalam Pinia Store yang dibangun (`useTodoStore`), ketiga konsep ini saling terhubung secara terpusat:

* **State (`ref`)**: ini berfungsi sebagai sumber kebenaran tunggal (*single source of truth*) yang menampung data mentah aplikasi.
  * `daftarTodo`: Array utama berisi seluruh objek tugas.
  * `kategoriAktif` & `kataKunciDebounce`: State pembantu untuk filter dan pencarian.

* **Getters (`computed`)**: Berfungsi membaca dan mengolah data dari `state` secara reaktif tanpa mengubah data aslinya.
  * `todoTersaring`: Menggabungkan state `daftarTodo`, `kategoriAktif`, dan `kataKunciDebounce` untuk menghasilkan daftar tugas yang cocok dengan pencarian pengguna.
  * `daftarKategoriComputed`: Mengambil kategori unik dari `daftarTodo` secara otomatis.
  * `getTodoById`: Getter berupa *higher-order function* untuk mengambil 1 task berdasarkan ID.

* **Actions (Fungsi)**: Berfungsi sebagai satu-satunya cara resmi untuk mengubah nilai pada `state`.
  * `tambahTodo()`, `toggleSelesai()`, `updateTodo()`, dan `hapusTodo()` mengubah isi `daftarTodo`.
  * `setKategoriAktif()` dan `setKataKunciDebounce()` mengubah state filter.

**Hubungan Ketiganya:**
Ketika pengguna memanggil **Action** (misal `tambahTodo`), data pada **State** (`daftarTodo`) berubah. Perubahan pada State secara otomatis mentrigger **Getters** (`todoTersaring`) untuk menghitung ulang hasilnya, sehingga tampilan UI yang mereferensikan Getter tersebut langsung diperbarui secara reaktif.

## 2. Perbandingan Eksplisit: Sebelum (Manual M3) vs Sesudah (Pinia M4)

### A. Apa yang SEBENARNYA Berubah di Kode?
* **Struktur Deklarasi Store:**
  * *Sebelum:* Menggunakan ekspor variabel `ref()` biasa di file JS manual (`const daftarTodo = ref([])`).
  * *Sesudah:* Dibungkus menggunakan `defineStore('todoM4', () => { ... })` milik Pinia.
* **Penempatan Logika Filter:**
  * *Sebelum:* Logika pencarian dan penyaringan data ditulis di level komponen (`TodoMain.vue`) menggunakan `computed()` lokal.
  * *Sesudah:* Dipindahkan total menjadi **Getters** di dalam Pinia store, sehingga komponen tinggal menerima data bersih.
* **Cara Import & Konsumsi Komponen:**
  * *Sebelum:* Import variabel langsung per biji (`import { daftarTodo, tambahTodo } from '...'`).
  * *Sesudah:* Menginisialisasi instance store utuh (`const todoStore = useTodoStore()`) dan mengakses atribut/fungsinya lewat objek `todoStore`.
* **Dukungan DevTools:**
  * *Sebelum:* Tidak terdeteksi secara otomatis di tab Pinia Vue DevTools.
  * *Sesudah:* Terintegrasi penuh dengan Vue DevTools untuk pelacakan state dan *time-travel debugging*.

### B. Apa yang TIDAK Berubah dari Sisi Komponen & Pengguna?
* **Perilaku Aplikasi (User Experience):** Dari sudut pandang pengguna, tampilan visual, alur pencarian, pemfilteran kategori, penambahan tugas, penandaan selesai, serta pengeditan detail task berjalan **100% identik dan persis sama**.
* **Integrasi Router:** Jalur navigasi utama dan komunikasi data antar-halaman tetap terjaga konsistensinya.
* **Refactor, Bukan Fitur Baru:** Seluruh proses perubahan ini murni berupa penataan ulang arsitektur kode (*refactor*) untuk meningkatkan *maintainability* tanpa mengubah *business logic* atau menambah fitur eksternal baru.
